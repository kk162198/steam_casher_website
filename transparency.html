實拿倍率怎麼算

這是全站所有數字的基礎。兩邊的手續費都在公式裡，沒有藏起來的部分。

項目 費率 誰付 說明

CSFloat 入金手續費
（我們用 7.5% 保守估）		 約 2.8% + US$0.30
依入金方式而異		 你 這筆錢是在「儲值到 CSFloat 帳戶」時付的，不是在買每一件商品時付的。網站的每件成本一律用 7.5% 計算——刻意抓得比實際高，寧可低估折扣。
Steam 市場手續費 15% 你（依賣家淨額計算） 含 5% Steam 手續費與 10% CS2 遊戲手續費，兩者都是對賣家淨額計算。

兩個手續費分量各有 US$0.01 的最低收費，所以低價品項的實際費率會高於 15%；換算到賣價上，一般品項的實際抽成約 13%。網站顯示的數字已經照 Steam 的實際計算方式算過。

CSFloat 那 7.5% 是我們自己抓的保守估計值，不是 CSFloat 公告的費率。 入金費是對「你儲值的總金額」收一次，不是每買一件收一次，所以攤到每件商品上的等效費率會隨你這次花多少而變動——花 NT$1,000 約 3.8%、花 NT$3,000 約 3.1%、花 NT$5,000 約 3.0%。我們沒有按金額動態調整，而是一律用 7.5%。 意思是：你實際拿到的折扣，通常會比網站上顯示的更好一點，不會更差。等我們用真實交易核對出確切費率後會更新這裡，並記在更新日誌。

完整算式

# 1. 你在 CSFloat 實際付出的成本（每件） # # CSFloat 不收買方市場手續費，你付的是掛牌價。 # 這裡多加的 7.5% 是「入金手續費」的保守估計值—— # 實際約 2.8% + US$0.30，且是對整筆儲值收一次、不是每件收一次。 # 我們刻意抓高，寧可低估折扣。 # csfloat_cost = csfloat_掛牌價 × (1 + 0.075) # 2. 你在 Steam 賣掉之後實際收到的金額（每件） # # steam_price 是買家付的錢，不是你拿到的錢。 # # Steam 的 5% + 10% 手續費是對「賣家淨額」計算， # 不是對賣價計算： # # 買家付的錢 = 賣家淨額 × 1.15 # # 所以從賣價反推淨額要用「除的」，不是乘 0.85。 # steam_income = steam_price ÷ (1 + 0.15) # 3. 稅後淨利（每件） # # 賣掉一件實際多拿多少，兩邊手續費都扣完了。 # diff = steam_income − csfloat_cost # 4. 實拿倍率：花 1 元換到多少 Steam 餘額 # # 低於 1 代表這個品項現在做會虧錢。 # ratio = steam_income ÷ csfloat_cost # 5. 換算成折扣：買同一款遊戲便宜幾 % # # 網站上顯示的「便宜約 N%」就是這個數字。 # discount = (1 − 1 ÷ ratio) × 100%

帶一組數字進去

# 已知條件（這兩個數字是從市場抓來的） # csfloat_掛牌價 = NT$ 93 steam_price = NT$ 152 # 1. 你在 CSFloat 要付多少 # csfloat_cost = 93 × 1.075 = NT$ 100 # 2. 你在 Steam 賣掉實際拿到多少 # # 152 是「近期中位成交價」，不是當下最低掛牌價。 # 我們兩個都有記錄，實測下來沒有系統性差距 # （平均 −0.19%，範圍約 ±7%），所以用哪個都不會 # 系統性高估或低估——但你實際掛單時看到的價格 # 會跟這裡有幾個百分點的出入，那是正常的。 steam_income = 152 ÷ 1.15 = NT$ 132 # 也就是說，買家付的 152 元裡， # Steam 抽走 20 元（約佔賣價 13%）。 # 3. 這一件實際賺多少 # diff = 132 − 100 = NT$ 32 # 4. 花 1 元換到多少餘額 # ratio = 132 ÷ 100 = 1.32 # 5. 換算成折扣 # discount = (1 − 1 ÷ 1.32) × 100% = 約 24%

帳面上 93 元的東西賣 152 元，看起來是 63% 的價差。扣完兩邊手續費之後，你實際的折扣是 24%。網站上顯示的一直都是後面這個數字。

怎麼算「7 天後賣價差多少」

  1. 把 CSV 依 name（品項）與 snapshot_date（日期）排好。
  2. 對每個品項、每個日期 d，找出 d + 7 天 那一筆。兩筆都存在才算數。
  3. 算 steam_price(d+7) ÷ steam_price(d) − 1，這就是那一組的 7 日賣價變動。
  4. 把所有組別彙總成分布（平均、中位、百分位、最差值）。

⚠️ 三個算的時候會踩到的地方：同一品項的相鄰視窗互相重疊（d 與 d+1 那兩段有 6 天是共用的）， 所以樣本數不等於獨立觀察數，直接套信賴區間會高估精確度； steam_price 是中位成交價，不是最低掛牌價； 還有下面這一條，是我們自己查資料時才發現的。

⚠️ 早期的資料是「單點取樣」，這會影響你算出來的結果

steam_price、csfloat_price 這些欄位， 2026-08-14 以前存的是每天某一個瞬間抓到的值，不是那一天的代表值。 而且那個「瞬間」其實不固定——排程設在 00:30 UTC，實際落在 02:28–04:06 之間。

我們用自己的資料量過這件事：判定「跳一下、隔天又彈回去」（真實的價格移動會延續，取樣噪音會彈回原位）， Steam 有 25%、CSFloat 有 30% 的大幅變動屬於這一類。也就是說早期序列裡約有四分之一的波動是取樣造成的，不是市場造成的。

2026-08-14 起改成每次抓價都記錄，隔日彙總成當天的中位數。 新欄位是 *_median（中位數，建議用這個）、 *_mean（平均，拿來對照）、 *_n（當天的樣本數）。 原本的單點欄位保留不動——已經下載過的版本要對得上，而且兩種取法並存才比較得出彙總修正了多少。

為什麼是中位數不是平均：一天抓 8 次，只要其中一次抓到離群的掛單，平均就會被拉走，中位數不會。 我們遇過一筆 US$0.05 的掛單把某個品項的倍率拉到 2 倍——那種情況平均擋不掉。 *_mean 留著就是給你比對用的：與中位數差很多，代表那一天有離群值。

這份資料量得到什麼、量不到什麼

✅ 量得到：市場報價在七天之內怎麼移動。這是完全客觀的，任何人拿同一份 CSV 都會算出同樣的數字。

❌ 量不到：你掛上去到底賣不賣得掉、賣在什麼價。 快照預設你能在報價成交，但冷門品項一天可能只成交幾十個——對那些品項，用快照算出來的結果會比現實好看。 這一段差距只有實際成交紀錄回答得了，見風險與限制。

我們暫時不在這裡公布自己算出來的結論。目前累積的天數還太少，而且如上所述視窗互相重疊， 這時候給一個看起來很精確的數字，正是我們在試算頁叫你別信的那種數字。 資料夠了會放上來，不管數字好不好看。
